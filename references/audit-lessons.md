# 审计实战教训（v3.29）

来源：2026-05-19 Perplexity Skill Schema 审计 → 修复 yinyo-writer

## 时序矛盾（最常见 bug）
- 步骤引用尚不存在的产物
- 例：Step 11 说"插入 HTML"但 Step 12 才生成 HTML → 模型跳过 Step 11
- 修复：每个步骤的产出物必须在引用时已存在

## 指令可操作性（自然语言陷阱）
- "调用 xxx skill" → 模型不会主动加载另一个 skill
- 修复：显式写 `skill_view('skill-name')` + 对应的工具函数名（`image_generate()` / `terminal()`）
- 模型读不懂自然语言指令——读懂了也只能跳过

## "在文件里" vs "在实际输出中" 检查
- 规则写在 layout 文件里 ≠ 生成流程会引用它
- 必须检查：该规则是否真的被某个 Step X 调用？
- 例：§9.3 Mac 终端块写在 layout 里但生成流程从未触发 → 无效规则

## 模型已知内容压缩
- 基础写作建议（开头/结尾/标题/节奏）模型已知道
- 保留 yinyo 特有的判断和案例，删掉通用部分
- 目标：SKILL.md < 50KB

## L5 检查必须覆盖完整
- 检查表必须包含所有已定义的样式
- 新增样式后立即补 L5 行，否则等于没加
